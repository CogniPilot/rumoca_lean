# Constant-rate development profile (G01)

The constant-rate profile is the first roadmap ring G01 increment: real
constants and independent states. It admits a model of two or more scalar
`Real` states, each with one derivative equation whose right-hand side is a
signed decimal literal:

```modelica
model ConstantRates
  Real x;
  Real y;
equation
  der(x) = 2.5;
  der(y) = -1;
end ConstantRates;
```

This profile is a development case. The production compiler still rejects it,
and this increment builds only the frontend, the source semantics and the Solve
lowering as package products. C emission, the FMI 3 and eFMI artifacts, and
production admission are later increments, each with its own lowering theorem,
target-execution theorem and actual-artifact certificate.

## Grammar and lexer

`constant_composition` is a fourth alternative of `composition`, kept separate
from the two admitted profiles so the grammar never mixes them:

```
constant_composition
    : component_clause ';' constant_component_list constant_equation_section
constant_component_list
    : component_clause ';' | constant_component_list component_clause ';'
constant_equation_section
    : equation constant_equation_list
constant_equation_list
    : constant_equation ';' | constant_equation_list constant_equation ';'
constant_equation
    : der '(' component_reference ')' '=' real_literal
real_literal
    : IDENT
```

Two or more declarations are required so that the shared prefix with the
admitted unit profile (`component_clause ';' …`) stays LALR(1); a single-state
constant model would collide with the unit case. The tables are regenerated by
`lake run generate` and stay conflict-free; `lake run check-generated` confirms
the checked-in tables, and the parser package audit passes with only the three
foundational axioms.

A rate is recognized as a single value-erasing number token. The lexer's number
rule munches the signed-decimal character class (`numberChar`) and emits a
`.literal` token for a pure digit run (unchanged from before, so the admitted
profiles' `'0'`, `'1'`, `'2'` literals are untouched) and an `.ident`-class
number token otherwise. The grammar therefore matches a rate through the
existing `IDENT` terminal, and resolution recognizes the base-ten content with
`parseDecimal`. The lexer soundness and completeness theorems (`scan_sound`,
`scan_complete`, `Lexes.spelled`) are extended to the new rule.

## Typed frontend

`ModelicaParser.Constant`:

- `Syntax.lean`: the AST (`Model` with `state0`, `state1`, `statesRest` and
  `equation0`, `equationsRest`, guaranteeing two states and one equation),
  `decode` with an exact-token guard, and the round-trip theorems `decode_sound`
  and `decode_complete`.
- `Parser.lean`: `in_grammar`, proved for every model of the AST by induction on
  the declaration and equation lists over the left-recursive
  `constant_component_list` and `constant_equation_list` productions, and the
  reusable `ParserActions.Actions` value.
- `Located.lean`: the located parse (`parseLocated`), the resolution predicate
  `Model.Resolved` and `LocatedParsed.resolve`.
- `Decimal.lean`: `parseDecimal`, recognizing the MLS 3.7 unsigned-real form
  with an optional sign and recording the exact base-ten `Decimal` content.

## Resolution

`Model.Resolved` requires:

- the end name matches the model name;
- the declared state names are distinct (a duplicate is rejected);
- the equations' derivative names are a permutation of the declared states, so
  every `der` reference is a declared state (no unbound name) and every state
  has exactly one equation (no uncovered state);
- every rate spelling parses as a signed decimal literal.

`LocatedParsed.resolve` reports the first failing condition with a diagnostic
range; `resolve_complete` shows a resolved model always succeeds.

## Semantics and Solve lowering

`RumocaCore.Constant`:

- The source system `Model.Solves`: each declared state's derivative equals its
  rounded rate; `Model.Initial`: every state initializes at `+0`.
- The prepared IVP `ConstantIVP n` stores one computable `Decimal` per state, in
  declaration order; `rateValues` is the exactly rounded binary64 rate vector
  and `initial` is the zero vector. `Model.lower` builds it.
- The lowering chain `Model.lowering_chain` and `Model.initialization_chain`
  relate the named source system to the indexed IVP.
- Exact rounding: `Decimal.rate` is `Scaled.round` of the literal's numerator
  and scale, and `Decimal.rate_rounds` is its round-to-nearest-even
  specification, reusing the unit profile's `1` machinery and the scaled
  rounding of `packages/core/RumocaCore/Real/ScaledRounding.lean` rather than
  duplicating it.
- Permutation invariance: `Model.decimalOf_perm`, `Model.rateOf_perm` and
  `Model.lower_rates_perm` show that reordering the equations preserves every
  state's rate, hence the whole IVP.

## Compiler preparation

`Rumoca.ConstantCompiler.prepare` parses, resolves and lowers a source string to
a `Prepared` value carrying the located parse and the multi-state IVP.
`Rumoca.ConstantCompiler.ConstantProofs` proves:

- `prepare_eq_parsed`: the located driver implements the same parse and
  resolution for a pinned AST.
- `Prepared.source_correct`, `prepare_correct`: the parsed tokens bind to the
  source (lexing and EBNF membership), and the source system and initialization
  are preserved in the stored IVP.
- `Prepared.rate_exact`: each stored rate value is the round-to-nearest-even of
  its literal's base-ten content.
- `prepare_perm_invariant`: the prepared IVP is invariant under permuting the
  equations.

The compiler regression executable (`packages/compiler/Tests/Main.lean`) parses
`examples/development/ConstantRates.mo`, checks the recovered states, derivative
references and rate spellings, checks a reordered source, asserts the production
compiler rejects the profile, and asserts the frontend rejects an unbound
reference, a duplicate declaration, a mismatched end name and a non-numeric
right-hand side.

## FMI 3 record profile reuse (Stage B1)

The FMI 3 tensor adapter storage, initializer and model description are
parameterized by a record profile (`dev/tensor-ad.md`, "Record profile
parameterization"). The constant-rate profile is the no-input, no-output
instance, and this stage generalizes the record without emitting any adapter:

- Storage: the constant instance heap (`FMI3.TensorInstance.constantStore`, the
  input-absent instance of the generic `storeOpt`) holds the time base, the state
  vector and its writable derivative. Its separation, other-instance preservation
  and readability/writability theorems are proved
  (`constant_reads_state`, `constant_writable_derivative`, `constant_fields_separate`,
  `constant_instances_separate`, `constant_store_other_instance`). The eventual
  constant adapter binds the kernel entries `rumoca_constant_rhs`,
  `rumoca_constant_step` and `rumoca_constant_sample`
  (`packages/backend-c/RumocaC/ConstantKernelCode.lean`) to these regions.
- Declarations: `FMI3.TensorStorage.regionMembersG shape false false` declares the
  time base, the state region and the derivative region (`layout_names_constant`),
  and the generic record tokenizes under the shared C scanner (`recordG_printed`,
  `storageG_printed`).
- Initialization: the reserved-record initializer is profile-independent, so
  `FMI3.ConstantInstanceInit` reuses `TensorInstanceInit` verbatim (fixed-zero
  state fill, reset time base, FMI lifecycle metadata).
- Model description: `FMI3.TensorMetadata.constantModelDescription`, universal in
  the state shape, declares the independent `time`, one array state variable `x`
  of the state shape (one `Dimension` per extent, no coordinate enumerated) and
  its derivative `der(x)`, with value references `0` time, `1` state, `2`
  derivative and an empty dependency set for the constant derivative. Its
  well-formedness, value-reference distinctness, dimension-product and
  model-identifier theorems are proved and recorded in
  `dev/standards-review.md`.

## Open obligations

The following are deferred to later increments, each with its own proofs and
actual-artifact certificate:

- C emission of the multi-state IVP with the ordered finite-arithmetic and
  storage contract, and its target-execution theorem.
- FMI 3 Model Exchange and Co-Simulation artifacts and the eFMI Algorithm and
  Production Code artifacts, bound to actual bytes.
- Production admission of the profile through the CLI.
- A bare unsigned-integer rate (no sign, point or exponent) and an
  exponent-form rate at the token level; these are recognized lexically but a
  bare integer keeps the existing literal class and is not admitted as a rate,
  and an exponent spelling is accepted by the grammar but its rounding is only
  exercised through `parseDecimal`, not yet in a fixture.
- A single-state constant model, which the current grammar excludes to keep the
  shared prefix with the unit profile unambiguous.
