# Expression development profile (G02)

The expression profile is the second roadmap ring G02 increment (dev/roadmap.md
"R2"): parameters, states and algebraic variables with acyclic arithmetic
equations. It targets small ODE models with expressions and parameters:

```modelica
model DampedOscillator
  parameter Real k = 1.5;
  parameter Real c = 0.2;
  Real x;
  Real v;
  Real f;
equation
  f = -k * x - c * v;
  der(x) = v;
  der(v) = f;
end DampedOscillator;
```

This profile is a development case. The production compiler still rejects it,
and this increment is grown in slices, each a checked package product. C
emission, the FMI 3 and eFMI artifacts, and production admission are later
increments, each with its own lowering theorem, target-execution theorem and
actual-artifact certificate.

## Admitted grammar (landed)

`expression_composition` is a further alternative of `composition`, kept
separate from the admitted and other development profiles so the grammar never
mixes them:

```
expression_composition
    : expr_parameter_list expr_variable_list expr_equation_section
expr_parameter_list
    : expr_parameter ';' | expr_parameter_list expr_parameter ';'
expr_parameter
    : parameter type_specifier ident '=' real_literal
expr_variable_list
    : component_clause ';' | expr_variable_list component_clause ';'
expr_equation_section
    : equation expr_equation_list
expr_equation_list
    : expr_equation ';' | expr_equation_list expr_equation ';'
expr_equation
    : der '(' component_reference ')' '=' expr
    | component_reference '=' expr
expr
    : expr '+' arith_term | expr '-' arith_term | arith_term
arith_term
    : arith_term '*' arith_factor | arith_term '/' arith_factor | arith_factor
arith_factor
    : '(' expr ')' | '-' arith_factor | arith_atom
arith_atom
    : IDENT
```

The profile admits one or more `parameter Real p = literal` declarations, one or
more `Real` declarations (states and algebraic variables share the plain `Real`
declaration form; they are distinguished by name resolution, not syntax), and an
equation section of `der(state) = expr` and `alg = expr` equations. Each `expr`
is an arithmetic expression restricted to `+ - * /` with unary minus,
parentheses, decimal literals and declared-name references. The grammar is
stratified into additive (`expr`), multiplicative (`arith_term`) and factor
(`arith_factor`) levels, so `*` and `/` bind tighter than `+` and `-`, every
binary operator is left associative, and parentheses override precedence, as in
the MLS 3.7 operator table. States and algebraic variables both lex as `IDENT`,
as do decimal literals inside expressions, so `arith_atom` is a single `IDENT`
leaf whose spelling resolution classifies.

The checked and runtime LALR(1) tables are regenerated by `lake run generate`
(268 canonical, 222 LALR states) with no shift/reduce or reduce/reduce conflict;
`lake run check-generated` confirms the checked-in tables. The reusable engine's
first-set, item, safety, progress, acceptance and execution certificates carry
over to the extended grammar (the generated `Rumoca.Generated.*` theorems), and
the parser package audit passes with only the three foundational axioms. The
larger source certificate and transition table elaborate under a raised
file-level `maxRecDepth` (emitted by the generator) and a larger Lean stack for
the `ModelicaParser` library.

## Lexer (landed)

Arithmetic operators are lexed as their own literal terminals. The source
punctuation set gains `*` and `/`, and a lone `+` or `-` (a sign with no
following digits) is emitted as an additive operator literal rather than a
value-erasing number token. A signed decimal spelling with digits (for example
`1.5` or `-1`) stays a single number token, so the admitted unit, driven, array
and constant profiles lex unchanged (`numberToken`, `scan_sound`,
`scan_complete` are extended, and the number-token classification proof in the
FMI 3 name path is updated). The fixture's `-k` therefore lexes as an operator
`-` followed by the identifier `k`, and `1.5` as one number token.

## Open obligations

The following are the remaining G02 slices, each to be added with its proofs and
(for the target slices) actual-artifact certificate:

- Typed frontend: the stratified expression AST, a minimal-parenthesization
  serializer and a precedence-respecting `decode`, with the round-trip
  soundness and completeness theorems and the `EBNF.Accepts` grammar-membership
  proof (`in_grammar`) instantiating the reusable action contract; the located
  parse; and name resolution. A design and a work-in-progress decoder with the
  soundness proof structure exist but are not yet part of the build.
- Source semantics: evaluation over an environment of Real values (parameters
  bound to their literals, states and algebraic variables as unknowns), name
  resolution rejecting duplicates and unbound names, and acyclic scheduling of
  the algebraic equations (dependency graph, topological order, cycle rejection
  with a diagnostic), with proofs that the scheduled order is valid, that
  scheduling is deterministic and permutation-invariant in the resulting
  state-to-derivative function, and that substitution of an algebraic variable
  by its defining expression preserves the real-valued meaning.
- Solve lowering and numerical refinement: lowering to a Solve model whose
  derivative function evaluates the scheduled algebraic assignments and then the
  derivative expressions, as an expression tree over binary64 with
  round-to-nearest-even on each operation and no reassociation; the lowering and
  initialization chains; and the refinement theorem that, with all intermediate
  operations finite, the lowered evaluation equals the elementwise rounded
  evaluation of the real expression tree in the source operation order. This
  slice also requires a round-to-nearest-even binary64 division and subtraction
  in the core arithmetic and their use in the derivative expression IR; the
  existing finite kernels model addition and multiplication only.
- Compiler preparation: `Rumoca.ExpressionCompiler.prepare` with `prepare_correct`,
  the fixture `examples/development/DampedOscillator.mo`, its compiler test ties
  (parsing, scheduling order, sample derivative values, rejection of a cyclic
  algebraic pair and of an unbound name), and the production `compile` rejection
  assertion.
- C emission, FMI 3 and eFMI artifacts bound to actual bytes, and production
  admission through the CLI.
